# Атака XSS

## Суть уязвимости

**XSS** (Cross Site Scripting, межсайтовый скриптинг) — тип атаки на веб-приложение, при котором в ответ сервера внедряется вредоносный код. Этот код выполняется в браузере пользователя при открытии страницы.

Атакующий подставляет в поля ввода (например, в форму гостевой книги) не обычный текст, а фрагменты HTML или JavaScript. Если приложение вставляет ввод пользователя в HTML **без экранирования** служебных символов (`<`, `>`, `&`, `"`, `'`), браузер воспринимает их как разметку или скрипт и выполняет. В результате злоумышленник может:

- украсть cookie или сессию;
- подменить содержимое страницы;
- перенаправить пользователя на фишинговый сайт;
- выполнить действия от имени пользователя в рамках текущего сайта.

## Как это происходит

1. **Ввод данных.** Пользователь (или атакующий) отправляет сообщение, в котором вместо обычного текста указана строка вида:
   ```html
   <script>alert('XSS')</script>
   ```
   или
   ```html
   <img src=x onerror="alert('XSS')">
   ```

2. **Сохранение.** Сервер сохраняет это сообщение в базу без проверки и экранирования.

3. **Вывод на страницу.** При отображении гостевой книги сохранённая строка вставляется в HTML страницы **как есть**. Шаблонизатор по умолчанию может не экранировать вывод, либо экранирование отключают ради «красивого» форматирования (например, подсветки слова «guestbook»).

4. **Выполнение в браузере.** Браузер получает HTML, видит теги `<script>` или атрибуты вроде `onerror` и выполняет код. Таким образом, вредоносный скрипт выполняется в контексте сайта у каждого, кто открыл страницу.

В уязвимом приложении цепочка выглядит так: **ввод злоумышленника → сохранение → вставка в HTML без экранирования → выполнение кода в браузере жертвы**.

## Защитные меры

Используют два **основных**, дополняющих друг друга подхода:

1. **Корректный вывод служебных символов.** Самые опасные символы — `<`, `>`, `&`, `"`, `'`. Их нужно заменять на сущности HTML (например, `&lt;`, `&gt;`, `&amp;`), чтобы браузер воспринимал их как текст, а не как разметку или скрипт. **Целесообразно включить «эскейпинг по умолчанию» в используемом шаблонизаторе.**

2. **Content Security Policy (CSP).** Заголовки CSP ограничивают источники скриптов, стилей и других ресурсов, что снижает последствия возможного XSS.
