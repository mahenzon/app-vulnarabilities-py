# Атака «SQL-injection»

## Суть уязвимости

Атака типа **Injection** позволяет атакующему внедрить произвольный код через приложение в другую систему (например, при выполнении внешних программ через shell или обращении к базам данных через SQL).

**SQL-инъекции** возникают, когда программа формирует запросы к базе данных **динамически**, подставляя в текст запроса данные из недоверенных источников (пользовательский ввод из формы, query-параметры URL, заголовки и т.д.) без проверки и экранирования.

Если в запрос попадает строка, в которой атакующий подставил фрагменты SQL (кавычки, ключевые слова `OR`, `UNION`, `--` и т.п.), СУБД воспринимает их как часть команды, а не как данные. В результате можно изменить логику запроса, прочитать чужие данные, удалить или изменить записи.

## Как это происходит

1. Приложение получает ввод пользователя (например, поисковую строку `title` или параметр сортировки `order`).
2. Строка запроса к БД собирается через конкатенацию или f-строку, и пользовательский ввод вставляется **напрямую** в SQL:
   ```python
   query = f"SELECT * FROM articles WHERE title LIKE '%{title}%' ORDER BY created_at {order}"
   ```
3. Атакующий подставляет в `title` или `order` не обычный текст, а фрагмент SQL, например:
   - `title`: `' OR '1'='1` — условие всегда истинно, возвращаются все строки.
   - `order`: `DESC; DROP TABLE articles; --` — выполняется второй, вредоносный запрос.
4. СУБД выполняет получившийся запрос как один или несколько корректных SQL-операторов, что и приводит к уязвимости.

Итог: **любой пользовательский ввод, попадающий в SQL в «сыром» виде, может изменить структуру и смысл запроса.**

## Защитные меры

- Никакой пользовательский ввод не должен попадать в SQL-запросы в сыром виде.
- Предпочтительно использовать **ORM**; если нужны свои запросы для оптимизации — только с **параметризованными запросами** (prepared statements), где данные передаются отдельно от текста запроса и приводятся к нужному типу:

  ```python
  items = db.execute(
      "SELECT * FROM articles WHERE title LIKE ? ORDER BY created_at ?",
      (f"%{title}%", order),
  ).fetchall()
  ```

  (Для имён колонок/направления сортировки параметризация не подходит — допустимые значения нужно проверять по белому списку.)
