# Атака CSRF (Подделка межсайтовых запросов)

## Проблема

**CSRF** (Cross-Site Request Forgery, Подделка межсайтовых запросов) — это вид атаки на посетителей веб-сайтов, использующий недостатки протокола HTTP.

### Как работает атака

Когда жертва заходит на сайт, созданный злоумышленником, от её лица тайно отправляется запрос на другой сервер (например, на сервер платёжной системы), осуществляющий вредоносную операцию (например, перевод денег на счёт злоумышленника).

### Условия для успешной атаки

Для осуществления CSRF-атаки необходимо:
- Жертва должна быть авторизована на том сервере, на который отправляется запрос
- Запрос не должен требовать подтверждения со стороны пользователя, которое невозможно подделать
- Атакующий скрипт может сформировать и отправить запрос без ведома пользователя

### Опасность

CSRF-атакам могут быть подвержены:
- Публичные веб-приложения
- Внутренние сервисы (недоступные напрямую извне)
- Панели администрирования
- API-эндпоинты, изменяющие состояние данных

Поэтому защита от CSRF критически важна для любых приложений, работающих с пользовательскими данными.

## Решение

### Основной принцип защиты

Все запросы на изменение состояния данных (создание, обновление, удаление) должны быть подписаны специальным **CSRF-токеном**.

### Механизм работы токена

1. **Генерация**: Сервер генерирует уникальный непредсказуемый токен для каждой сессии или запроса
2. **Встраивание**: Токен встраивается в HTML-формы или передаётся в заголовках
3. **Проверка**: При получении запроса сервер проверяет наличие и корректность токена
4. **Отклонение**: Запросы без валидного токена отклоняются

### Пример реализации в HTML

```html
<form method="post" action="/transfer">
    <input type="hidden" name="csrf_token" value="УНИКАЛЬНЫЙ_ТОКЕН"/>
    <input type="text" name="recipient" placeholder="Получатель"/>
    <input type="number" name="amount" placeholder="Сумма"/>
    <button type="submit">Отправить</button>
</form>
```

### Пример проверки на стороне сервера

При обработке POST-запроса сервер должен:

```python
# Псевдокод
def process_transfer(request):
    # 1. Извлечь токен из запроса
    token_from_request = request.form.get('csrf_token')

    # 2. Получить ожидаемый токен из сессии
    expected_token = request.session.get('csrf_token')

    # 3. Сравнить токены
    if not token_from_request or token_from_request != expected_token:
        raise SecurityError("Invalid CSRF token")

    # 4. Выполнить операцию только если токен валиден
    perform_transfer(request.form.get('recipient'), request.form.get('amount'))
```

### Дополнительные меры защиты

1. **SameSite cookies**: Установка атрибута `SameSite=Strict` или `SameSite=Lax` для cookies предотвращает их отправку в межсайтовых запросах

2. **Проверка заголовка Origin/Referer**: Проверка, что запрос пришёл с того же домена

3. **Требование подтверждения**: Для критических операций (например, смена пароля, большие переводы) требовать дополнительное подтверждение (пароль, 2FA)

4. **Ограничение времени жизни токена**: Токены должны иметь срок действия
